# SPEC R-020 + R-021 — OpenCode card and sign-in guidance for other agents

Requirements: `Requirements.md` R-020 (✅) and R-021 (✅). Base: `536bd6e` (R-018 and R-019 merged). Phase 3, one phase,
Writing Owner 3 (Codex GPT-6-Luna). Owner decisions 2026-11-13: on OpenCode 2.x run `opencode auth list --format json`
through the existing service (no `--standalone`); check at app start and on Re-detect only; on OpenCode 1.x read provider
names and types from `auth.json`.

## Facts (research 2026-11-13, official repositories and docs; no CLI was run, no credential file was read)

- OpenCode has two live generations. Repo https://github.com/anomalyco/opencode (`sst/opencode` no longer resolves).
  - 1.x (npm `opencode-ai` latest 1.19.5): `opencode auth list` (= `providers list`, alias `ls`) prints a human TUI list
    with ANSI colour and box glyphs, no JSON flag. Credentials: `<data>/opencode/auth.json`, data = `XDG_DATA_HOME` or
    `~/.local/share` (Windows: `%USERPROFILE%\.local\share\opencode\auth.json`, inferred). Shape: object keyed by provider
    id; value `{"type":"oauth",refresh,access,expires,…}` | `{"type":"api",key,metadata?}` | `{"type":"wellknown",key,token}`.
    Secret fields: `refresh`, `access`, `key` (api), `token`. Source: `packages/opencode/src/cli/cmd/providers.ts`,
    `packages/opencode/src/auth/index.ts` at tag v1.19.5; docs `services/site/src/docs/v1/content/cli.mdx`.
  - 2.x (GitHub release v2.2.7, package `@opencode/cli`): `opencode auth list [--format default|json]`. JSON:
    `[{ "id", "name", "connections": [ {"type":"credential","id":"cred_…","label","method":"key"|"oauth"|"external",
    "status"?:{"status":"needs_auth","message","url"?}} | {"type":"env","name":"<ENV_VAR>","status"?} ] }]`, no secret
    values (env var names are not values but are still not shown, F5b); nothing connected → `[]` (default format prints "No authenticated integrations"). Errors → stderr, exit 1.
    The command contacts the OpenCode background service and starts it if it is not running. Credentials live in
    SQLite `opencode.db`; a legacy `auth.json` is imported once and then not updated. `opencode auth export` prints
    secrets — never call it. Source: `packages/cli/src/commands/handlers/auth/list.ts`, `packages/schema/src/connection.ts`
    at tag v2.2.7; docs `services/site/src/docs/content/cli/providers.mdx`.
  - Login: `opencode auth login` (both generations; `/connect` inside the TUI).
- ccusage (https://github.com/ccusage/ccusage, v20.0.50) supports 19 agent ids: claude, codex, opencode, amp, droid,
  codebuff, cline, hermes, pi, goose, openclaw, kilo, kimi, qwen, copilot, gemini, antigravity, grok, zcode.
- GitHub Copilot CLI (https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli):
  `copilot login` in a terminal (`--web-flow` / `--device-code`), or `/login` inside Copilot CLI; or a fine-grained
  personal access token with the "Copilot Requests" permission in `COPILOT_GITHUB_TOKEN`, `GH_TOKEN` or `GITHUB_TOKEN`.
- ZCode (https://zcode.z.ai/en/docs/install, https://docs.z.ai/devpack/tool/zcode): desktop app; click **Connect** at the
  bottom left and choose "Connect Z.ai", "Connect BigModel" or "Use API Key"; API keys also under Settings → Model
  Providers. No CLI login command is documented.
- Code: `ConnectionsViewModel` has three `ConnectionCardViewModel`s (Claude, OpenAI, AGY) fed by
  `Update(snapshots)`; a card with no snapshot shows "Checking...". `ProviderMeta.All` also drives the Settings provider
  toggles (`SettingsViewModel`), so OpenCode must not be added to it. `App.OpenConnectDialog` calls
  `ProviderMeta.TryGet` and `ConnectionStore.GetAsync(id)` before showing the dialog. `Connections.RedetectRequested`
  calls `RefreshAsync(id)`. ccusage results reach `MainWindowViewModel.OnAgentUsageUpdated(lastGood, lastError)`;
  `AgentUsagePresenter.AgentDisplayName` maps known ids. Process pattern: `CcUsageRunner` (injected start function,
  deadline, output cap, kill tree, stdin closed).
- `.cmd` launch check (Coding Owner, 2026-11-13, this machine, .NET 11 / PowerShell 7.7): a `.cmd` at a path containing a
  space, started with `new ProcessStartInfo(fullPath)`, `UseShellExecute=false` and `ArgumentList` = `auth`,`list`,
  `--format`,`json`, ran and echoed `ARGS=[auth list --format json]`, exit 0 (Windows starts the command interpreter for
  a batch file implicitly). The arguments are fixed tokens with no quotes, `%`, `^`, `&` or user input, so batch
  argument re-parsing cannot change them.

## Changes — R-020 (OpenCode card)

| Id | Where | Requirement |
|---|---|---|
| F1 | Application: new `OpenCode/OpenCodeAuthStatus.cs` + `IOpenCodeAuthReader` | `OpenCodeAuthStatus(bool Installed, string Source, IReadOnlyList<OpenCodeSignIn> SignIns, bool MayBeOutdated, string Error)`; `OpenCodeSignIn(string Name, string Kind)`. `Task<OpenCodeAuthStatus> ReadAsync(CancellationToken)`. The type carries no secret field and `ToString` shows only names and kinds. |
| F2 | Infrastructure: new `OpenCode/OpenCodeAuthReader.cs` | Resolve exactly like `CcUsageRunner.ResolveExecutable` (rooted, non-drive-relative PATH entries in order; `opencode.exe` before `opencode.cmd` in each directory). Not found → `Installed=false`, no error. Launch exactly like `CcUsageRunner.BuildStartInfo` (proven with the npm `ccusage.cmd` shim): `new ProcessStartInfo(resolvedFullPath)`, `UseShellExecute=false`, `CreateNoWindow=true`, stdin/stdout/stderr redirected, UTF-8 (no BOM, throw on invalid), stdin closed after start, `Environment["NO_COLOR"]="1"`, arguments only through `ArgumentList` with the fixed tokens `--version` or `auth`,`list`,`--format`,`json` (no string concatenation, no `cmd.exe /c`, no user input in arguments; .NET quotes a path with spaces). Timeouts: `--version` 10 s, `auth list` 20 s. Caps: stdout 4 KB (`--version`) / 256 KB (`auth list`); stderr read and discarded (cap like `CcUsageRunner`). Kill the process tree on timeout, cap or cancel. Never any other subcommand, never `--standalone`, never `auth export`. The process start is injected (`Func<ProcessStartInfo, IOpenCodeProcess>`) like `ICcUsageProcess`, and so are the PATH/env/file reads, so tests never run the real `opencode`. |
| F3 | same | 2.x JSON: for each element take `name` (fallback `id`); for each connection: credential `method` oauth → "OAuth", key → "API key", external → "External", other → "Other"; `status.status == "needs_auth"` appends " (needs sign-in)"; env → "Environment" (the variable name is never kept, F5b). Never keep `id`, `label`, `message` or `url` of a connection. `[]` → installed, zero sign-ins. Strict: a non-array root, an element that is not an object, missing both `name` and `id`, or a connection without a string `type` → the command is treated as failed (F5). |
| F4 | same | `auth.json` path: `%XDG_DATA_HOME%\opencode\auth.json` when `XDG_DATA_HOME` is set and rooted, else `%USERPROFILE%\.local\share\opencode\auth.json`. Read at most 1 MB and parse with `JsonDocument`; other fields are parsed transiently but never copied, retained, formatted or logged — only each top-level property name and the value's `type` string are used: oauth → "OAuth", api → "API key", wellknown → "Well-known", any other or missing `type`, or a value that is not an object → "Other". Ignore `OPENCODE_AUTH_CONTENT`. |
| F5 | same | Outcomes (one each): **not on PATH** → `Installed=false`. **`--version` fails** (start error, exit ≠ 0, timeout, cap) or its text has no digit → version unknown. **Major = 1** → F4, `Source="auth.json"`, `MayBeOutdated=false`, missing file → zero sign-ins. **Version unknown** → F4 with `MayBeOutdated=true`. **Major ≥ 2** → F3, `Source="opencode auth list"`; if the command fails (start error, exit ≠ 0, timeout, cap, invalid JSON or shape) → F4 with `MayBeOutdated=true`. **auth.json unreadable** (IO/permission error), larger than 1 MB, invalid JSON or a root that is not an object → `Error`; when F4 is a fallback (`MayBeOutdated=true`) a missing file is also `Error`. `Error` text is always exactly "Could not read OpenCode sign-ins. Run `opencode auth list` in a terminal to check." **Cancellation** → `OperationCanceledException` propagates (no status). The reader throws nothing else; inner exceptions are not kept. Never put stdout, stderr, exception text, file paths or any secret into `Error`, `Source`, `ToString`, logs or exceptions. |
| F5b | same | Display names are untrusted and pass an allow-list before they are kept: provider names (`name`, fallback `id`, auth.json property names) must match `^[A-Za-z0-9][A-Za-z0-9 ._()+/@:-]{0,47}$` after trimming; otherwise the entry is kept with Name "Unnamed provider". Owner decision 2026-11-13 (Inspector A round 3): provider names/ids are identifiers by design, not secrets, and are shown when they pass this allow-list (so custom providers stay visible); env var names are never shown — the kind is always just "Environment". No other text from OpenCode (connection `id`, `label`, `message`, `url`, any value) is ever kept. A well-known URL key from auth.json therefore shows as "Unnamed provider" unless it matches. |
| F6 | `ProviderMeta` | New static `OpenCode` (not in `All`): Id "opencode", DisplayName "OpenCode", BadgeLetter "O", Tagline "OpenCode CLI · provider sign-ins", NeedsKey false, empty key/extra fields, SetupHint: "Install OpenCode, then sign in from a terminal: run `opencode auth login` and choose a provider (or use /connect inside OpenCode). Run `opencode auth list` to check your sign-ins.\n\nThis app runs `opencode --version` and `opencode auth list` to show provider names and sign-in types — never keys or tokens — and never signs in, signs out or edits OpenCode's files. On OpenCode 2.x that command talks to OpenCode's background service and starts it if it is not running, as any OpenCode command does; a service started for the first time may import an older auth.json into OpenCode's own database (OpenCode's normal upgrade step, not done by this app). OpenCode usage and cost in the OpenCode tab still come from ccusage." `TryGet("opencode")` returns it (the OpenCode tab's setup card may show this hint; its data source does not change). |
| F7 | `ProviderConnectionStore` | `GetAsync("opencode")` returns a secret-less connection without reading secrets (like agy); `SaveAsync("opencode", …)` with a key or extra throws like agy and writes nothing. |
| F8 | `ConnectionCardViewModel` / `ConnectionsViewModel` | `OpenCodeCard` (badge hue = series index 3, set explicitly because OpenCode is not in `All`) is appended to `Cards` after AGY. `Update(snapshots)` updates only Claude, OpenAI and AGY; it never touches `OpenCodeCard`. New `UpdateOpenCode(OpenCodeAuthStatus?)`: null → "Checking...". Not installed → "Not connected" / "–", Account "OpenCode not found on PATH", SourceLine "Install OpenCode, then run `opencode auth login`". Installed, zero sign-ins → "Not connected", Account "No providers signed in", SourceLine "Run `opencode auth login` to sign in". Sign-ins → "Connected" / "✓", Account "Signed in: " + `Name (Kind)` joined with ", " in reader order, SourceLine "Detected from opencode auth list" or "Detected from auth.json", plus "  -  may be out of date (OpenCode 2.x keeps sign-ins in its database)" when `MayBeOutdated`. Error → "Unavailable" / "!", Account "Could not check", SourceLine = `Error`. Button "Sign-in help" in every state. |
| F9 | `MainWindowViewModel` + composition (`App.xaml.cs`) | Optional `IOpenCodeAuthReader` (null → the card stays "Checking..." and nothing runs). The OpenCode check is a separate trigger, not part of `RefreshAsync`: new public `RequestOpenCodeCheck()`. Callers: (a) `App` once at startup, next to the initial refresh; (b) `Connections.RedetectRequested` with id null ("Re-detect all") → the existing `RefreshAsync(null)` **and** `RequestOpenCodeCheck()`; (c) id "opencode" → only `RequestOpenCodeCheck()` (no provider refresh). The timer, the Refresh button, the widget refresh and the `_pendingRefresh` rerun never call it. Coalescing: idle → start a read; a request while a read is in flight sets one pending flag (any number of requests → one rerun after the current read). Each completed read is applied via `Connections.UpdateOpenCode` on the view model's context (same delivery rule as agent usage: captured `_uiContext`, inline when none); the read runs off the UI thread; a fault other than cancellation shows the F5 `Error` text; nothing is awaited by provider refresh. |
| F10 | `App.OpenConnectDialog` | "Sign-in help" on the OpenCode card opens the existing dialog in its no-key form ("OpenCode sign-in", SetupHint, Close). |

## Not included

No login on the user's behalf; no writes to OpenCode files or its database; no `opencode auth export`; no reading of any
agent's credentials other than OpenCode's `auth.json` names/types; no new tab, gauge or quota; the OpenCode tab still uses
ccusage; no periodic `opencode` runs.

## Tests (Test Author, from this spec)

1. Reader (fake process start, fake file system/env; never the real `opencode`): not on PATH; version 1.x → auth.json;
   2.x JSON mapping for every method/status/env case; `[]`; exit 1 / timeout / cap / invalid JSON → auth.json with
   `MayBeOutdated`; every F5 outcome row; XDG path; 1 MB cap; unknown type → "Other"; `.exe` preferred over `.cmd`;
   the `ProcessStartInfo` (file name, `UseShellExecute=false`, exact `ArgumentList`, `NO_COLOR`); kill on timeout/cap;
   cancellation; a sentinel secret placed in every secret field of auth.json, in the 2.x connection `id`/`label`/
   `message`/`url`, and in stdout noise and stderr, never appears in the status, its `ToString`, `Error`, the card text or
   any exception message; F5b: a sentinel containing a character outside the allow-list (e.g. `=`, `"` or an ANSI
   escape) placed in `name`, `id` and an auth.json property name yields "Unnamed provider", and an allowed-character
   sentinel placed in an env var name never appears (kind "Environment"); neither reaches the status, `ToString` or
   (through `UpdateOpenCode`) the card's Account and SourceLine.
2. Card (F8): every state's word, glyph, Account, SourceLine and button; `Update(snapshots)` never changes `OpenCodeCard`;
   badge hue index 3.
3. Store (F7) and ProviderMeta (F6) verbatim texts; Settings provider toggles unchanged.
4. View model (F9): `RequestOpenCodeCheck` starts one read; `RefreshAsync` (timer/manual/pending rerun) never starts
   one; Re-detect all → provider refresh + one read; Re-detect "opencode" → one read and no provider refresh; three
   requests during an in-flight read → exactly one rerun; delivery on the view model's context; a faulted reader shows
   the F5 text; null reader → card stays "Checking...".
5. Other agents (G1–G4): exclusion list, case-insensitive dedupe, order, verbatim guidance, all four status texts, rows
   from `lastGood` when an error follows; both isolation directions: an exception in `UpdateOtherAgents` does not stop
   the existing tab updates, and an exception in an existing tab update (e.g. a throwing OpenCode/AGY composition seam)
   does not stop `OtherAgents` from updating.
6. Connections page renders with the new card and section in both themes (existing view tests pattern).
